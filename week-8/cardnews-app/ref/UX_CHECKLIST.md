# 카드뉴스 자동화 — 초기 UI/UX 요청 체크리스트

견적서 작업에서 후행적으로 추가했던 사항 + 카드뉴스 특화 캔버스 편집 요건을 정리. **V1 스펙에 미리 포함해서 요청하면 작업 반복이 크게 줄어듦.**

---

## A. 반복되는 편집 UX 패턴 (견적서에서 후행 추가했던 것들)

### A1. 인라인 편집 + 자동 저장
- 모든 텍스트 필드는 **클릭하면 그 자리에서 편집** (별도 '편집' 모드 / 모달 금지)
- blur·focus-out 시 자동 PATCH 저장. "저장" 버튼은 두지 않음 (전체 저장 같은 의도적 액션만)
- "saved 2s ago" 같은 상태 표시 한 줄

### A2. 키보드 동작 규칙 통일
| 키 | 동작 |
|---|---|
| Enter (단독, 한 줄 input) | 같은 그룹 다음 칸으로 이동 |
| Enter (마지막 칸) | 새 항목 추가 + 포커스 |
| **Shift+Enter** | **줄바꿈** (textarea 전환) |
| Esc | 편집 취소 (원래 값 복귀) |
| Tab | 다음 input |
| Cmd/Ctrl+Z, Shift+Z | 전역 undo/redo |

→ V1 스펙에 `enterNext()` 같은 헬퍼를 처음부터 만들어 모든 input에 적용.

### A3. 모든 리스트에 "+ 추가 / ▲ / ▼ / ×" 4종 세트
- 페이지·블록·텍스트 항목·아이콘 등 **순서가 있는 모든 컬렉션**에 4개 버튼 기본 제공
- 드래그 정렬도 함께 (▲▼는 정밀 조정, 드래그는 빠른 재배치)
- 새로 추가된 항목은 **자동 포커스 + 스크롤** (목록 끝/원하는 위치)
- "맨 위로 추가" 옵션 필요 (견적서에서 스콥 추가했을 때 최하단에만 생긴 게 문제였음)

### A4. 친절 UI vs Raw JSON
**다음 형태는 절대로 JSON textarea로 두지 않음.** 처음부터 친절 UI:
- `[{title, body}]` 같은 객체 배열 → 카드 리스트 에디터
- `[number, number, ...]` 7개 같은 고정 길이 → 라벨드 number-input 그리드
- `{client, partners:[{role,name}]}` 같은 중첩 → 섹션별 폼
- 0~10 같은 범위 숫자 → `<input type="number" min max>`
- 3~4개 enum → 라디오 버튼 그룹 (select 금지)
- URL + label 쌍 → `[label][url]` 분리 입력 (절대 `"label|url"` 문자열 금지)

JSON 탭은 비상시 raw fallback으로만 유지 가능.

### A5. 멀티라인 텍스트 전반 지원
- 제목·캡션·본문 등 사용자가 **줄바꿈을 넣고 싶을만한 모든 곳**은 처음부터 textarea
- 프리뷰 렌더링도 `white-space: pre-wrap`으로 줄바꿈 보존
- 자동 row 높이 증가 (`rows = max(1, lineCount)`)

## B. 카드뉴스 특화 — 캔버스 편집 (NEW)

### B1. 블록 모델
- 모든 요소(텍스트·이미지·스티커·도형)는 **공통 Block 인터페이스**: `{id, type, x, y, w, h, rotation, z, locked, hidden}`
- 페이지 = Block 배열. 페이지는 캔버스(예: 1080×1080) 위에 자유 배치

### B2. 선택·이동·변형 — 마우스
- 클릭: 선택 / 빈 곳 클릭: 선택 해제
- 더블클릭: 텍스트 블록 인플레이스 편집 진입
- 드래그: 이동. **Shift+드래그** = 축 잠금(수평/수직), **Alt/Option+드래그** = 복제
- 8방향 핸들(코너 4 + 변 4)로 리사이즈. **Shift** = 비율 유지
- 회전 핸들 별도(상단 위쪽). **Shift** = 15° 스냅
- Shift-클릭 / 영역 드래그로 **다중 선택**
- 가이드: 다른 블록·캔버스 중심·여백 기준 **스냅 + 정렬선**

### B3. 키보드 조작
- `←↑→↓` = 1px 이동, **Shift+화살표** = 10px
- `Delete/Backspace` = 선택 블록 삭제
- `Cmd+D` = 복제 (같은 페이지)
- `Cmd+]/[` = z-order 앞/뒤
- `Cmd+G` = 그룹(선택), `Cmd+Shift+G` = 그룹 해제
- `Esc` = 선택 해제 / 텍스트 편집 빠지기
- 모든 단축키 표시하는 **? 키 단축키 가이드 패널** 필수

### B4. 텍스트 블록 특수 기능
- **Auto-fit**: 영역 안에 텍스트가 안 들어가면 폰트 크기 자동 축소 (옵션)
- 한국어 줄바꿈 규칙: `word-break: keep-all`, `overflow-wrap: anywhere`
- 행간·자간 슬라이더 (인스타 카드뉴스 핵심 디자인 요소)
- 정렬: 좌/중/우/양끝
- 폰트 패밀리 선택 (브랜드 폰트 세트 미리 등록)

### B5. 잠금 / 숨김
- 배경·로고 같은 건 **잠금**해서 실수로 안 움직이게
- 잠금 토글 / 숨김 토글 한눈에 보이는 레이어 패널

### B6. 정렬·배치 보조 도구
- 선택 2개 이상: 좌/중/우 정렬, 상/중/하 정렬, 가로/세로 균등 분포
- 캔버스 기준: 중앙 정렬, 좌우 마진 자동

## C. 두 가지 뷰 모드 — 슬라이드 스크롤 ↔ 전체 그리드

### C1. 공통 상태 동기화
- 두 뷰가 **같은 Zustand store**를 바라보게 (편집·이동이 어느 쪽에서나 즉시 양쪽에 반영)
- 현재 선택된 블록 / 현재 페이지 / 포커스 필드 = 전역 상태

### C2. 슬라이드 스크롤 뷰 (견적서 레이아웃 유사)
- 좌측: 현재 페이지 1장만 크게 (실제 크기에 가깝게)
- 우측 사이드바: 현재 페이지의 블록 리스트 + 속성 패널
- 페이지 썸네일 strip(좌 또는 상단) — 클릭 시 점프
- 페이지 간 스크롤 = 다음/이전 페이지로 부드럽게

### C3. 전체 그리드 뷰 (피그마/일러 캔버스 유사)
- 모든 페이지를 격자로 보여줌 (예: 3×N 그리드)
- 페이지 간 드래그로 순서 변경
- 블록 클릭 = 인라인 편집 가능 (작은 스케일이지만)
- 페이지 복제 / 삭제 / 잠금 = 페이지 헤더 메뉴

### C4. 뷰 전환
- 단축키 1개로 토글 (예: `Cmd+1` 슬라이드 / `Cmd+2` 그리드)
- 전환 시 **현재 선택 블록 유지** + 그 페이지로 자동 스크롤

## D. JPG 저장 / Export

### D1. 단일 / 일괄
- 페이지 우상단 메뉴에 **"이 페이지 JPG 저장"**
- 헤더에 **"전체 JPG 저장 (ZIP)"** — 파일명 자동 `{template}-{nn}.jpg`

### D2. 해상도 옵션
- 1x (1080) / 2x (2160) / 3x (3240) 선택
- 기본 2x (Instagram·SNS용 적정)

### D3. WYSIWYG 보장
- export 결과가 화면과 픽셀 단위로 동일해야 함 (canvas 또는 html2canvas/satori)
- 폰트 로딩 완료 보장 (`document.fonts.ready` 대기)
- 미리보기 모드 (가이드선·핸들 숨김 상태) 토글

### D4. 메타 보존
- 워터마크 옵션 / SafeArea 가이드 (인스타 1:1·4:5 동시 export)

## E. 템플릿 / 상태 관리 (홈)

### E1. 3-tier 분류
- **템플릿** / **작업중** / **작업완료** 탭
- 카드 클릭 시 편집 진입
- 우상단 액션: "복제", "템플릿으로 저장", "삭제(소프트)"

### E2. 템플릿화
- "작업완료 → 템플릿으로 저장" 시: 텍스트 일부를 **변수 슬롯**으로 마스킹할지 선택 (예: 헤드라인, 브랜드명 변수)
- 또는 그냥 통째 복사

### E3. 신규 생성 = 깊은 복사
- 템플릿에서 새로 시작 시 deep-clone. 원본 템플릿은 절대 변경 안 됨
- 새 작업물은 자동으로 "작업중"

### E4. 필터·정렬
- 태그 / 클라이언트 / 카테고리 / 수정일 정렬
- 검색 (텍스트 일부)

## F. 자료실 / 라이브러리 (자주 쓰는 것들)

견적서의 "★ 라이브러리"와 동일한 패턴:
- **자주 쓰는 텍스트 블록** (브랜드 슬로건·CTA 문구 등)
- **스티커 라이브러리** (이모지·아이콘·도형 프리셋)
- **컬러 팔레트 / 폰트 세트** (브랜드별 저장)
- **이미지 자산** (썸네일 그리드, 검색)

→ 우측 패널의 별도 탭 또는 좌측 슬라이드 패널

## G. 자동저장·복원·이력

### G1. 자동저장
- debounce 300~500ms 후 PATCH
- "saved 2s ago" / 충돌 감지 시 "다른 탭에서 수정됨" 알림

### G2. Undo/Redo
- 캔버스 편집에선 **필수** (실수가 잦음)
- Cmd+Z / Shift+Cmd+Z, 스택 50~100 step
- 페이지 추가·삭제·순서 변경도 모두 stack에 포함

### G3. 버전 스냅샷
- "지금까지" 버튼 = 현재 상태를 명명된 스냅샷으로 저장
- 작업완료 시점에 자동 스냅샷

## H. 캔버스 사이즈 / 종횡비

- 1:1 (1080×1080), 4:5 (1080×1350), 9:16 (스토리·릴스), 16:9 옵션

## J. V1 빌드 전 결정해야 할 8가지

1. 캔버스 렌더 엔진: HTML/CSS (DOM) vs Konva.js (Canvas) vs Fabric.js?
   - DOM이 가장 만들기 쉬움 (텍스트 편집 자연스러움). 정밀 export는 satori 또는 html2canvas
2. 상태 관리: Zustand (견적서와 동일)
3. 자동저장 백엔드: Supabase Postgres (워크스페이스 흡수) vs 새 테이블?
4. 이미지 저장: Supabase Storage (워크스페이스 통일 규칙대로)
5. Undo 구현: 패치 기반(immer + 스택) vs 스냅샷 기반?
6. 텍스트 폰트 임베딩: 시스템 / Pretendard / Archivo Narrow 외 추가 폰트 허용?
7. 배포: novound-workspace 안에 `/cardnews` 라우트로 흡수? 또는 별도 Next.js 앱(견적서처럼)?
8. 권한: 워크스페이스 JWT 그대로 사용? 다른 사용자(에이전시 협업) 분리 필요?

## 참고: 견적서 작업에서 후행 추가했던 항목 목록

V1에서 빠뜨려서 나중에 요청한 것들:
- 스콥 순서 ▲▼ 이동 (재번호화 + timeline/pages 바인딩 동기화)
- 스콥명 Shift+Enter 줄바꿈 (input → textarea)
- 갤러리 비율 선택 (4:3 / 4:5 / 원본) — DB migration까지 동반
- stats/credits/points raw JSON → 친절 UI 분해
- points 키 이름 불일치 (`title` vs `subtitle` — 공개 사이트 스키마와 어긋남)
- 누락된 데이터 복구 (frutrip/writeyolife/hlllo points)

이런 종류는 **데이터 모델 결정 시 양쪽(편집 UI + 출력 페이지) 스키마를 같이 보고 결정**해야 후행 마이그레이션을 피할 수 있음.
